The basics

What this integration actually does

ShipStation's own WooCommerce connector handles the simple case well, and for one store with standard shipping it may be all you need. We'll say so if that's you. It runs out at the edges: split shipments, multi-warehouse routing, custom packing rules and order statuses that don't match the defaults.

This integration sends each order to ShipStation with the address, items, weights and any custom fields your packers need, then applies your routing and service rules. It writes the shipment data (carrier, service, tracking number and cost) back to the WooCommerce order, so the customer email fires and support can answer without leaving the store. Because WooCommerce is self-hosted, we can enrich the order first, resolving bundles into pickable parts, deriving package sizes from product data and tagging orders for the right warehouse.

Data flow

What syncs, and which way

Most WooCommerce and ShipStation projects cover the same six areas. Multi-warehouse and split-shipment handling is where most of the scoping time goes.

Orders

  • WooCommerce → ShipStation

Address, items, weights and the custom fields your packing bench needs.

Packing detail

  • WooCommerce → ShipStation

Bundles are resolved to components, with dimensions derived from product data.

Routing rules

  • Within ShipStation

Warehouse, carrier and service are chosen from the order's attributes.

Shipments and tracking

  • ShipStation → WooCommerce

Carrier, service, tracking number and cost are written to the order.

Customer notification

  • In WooCommerce

The order is marked complete, so the shipping email fires automatically.

Returns

  • ShipStation → WooCommerce

Return labels and received returns show against the original order.

Choosing a route

Four ways to build it, and when each one fits

ShipStation exposes a REST API and webhooks. The real question is how much sits between it and WooCommerce, and the answer is often a thin layer plus some store-side enrichment.

Official connectorShipStation's own WooCommerce integration

Best when you run one store with standard shipping and no custom rules.

Trade-off limited field control, and awkward with split shipments and bundles.

ShipStation REST APIOrders, shipments and labels

Best when you need custom field mapping, several warehouses or split shipments.

Trade-off rate limits on high-volume accounts.

ShipStation webhooksCallbacks when a shipment is created

Best when tracking should flow back the moment a label prints.

Trade-off you need a reliable listener with retry handling.

WordPress plugin hooksPHP inside the store

Best when orders need dimensions, warehouse tags or packing notes added first.

Trade-off the code lives in your site and must survive core updates.

If you run one warehouse, ship standard parcels and don't use bundles, ShipStation's own connector will probably do the job, and we'll say so. Custom work earns its cost at multi-warehouse routing, split shipments, or when the packing bench needs data the default connector won't send.
